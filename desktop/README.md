# anyscribe desktop app (Mac first)

An Electron shell around the anyscribe engine: it starts `python -m anyscribe ui`
on a port of its own, shows the existing dashboard in its window, and lives in
the menu bar. Plain JavaScript, Electron 44.9.3 pinned exactly, no other
dependencies. Packaging (electron-builder, the bundled Python, updates) is a
later phase; today this runs in dev only.

## Run it in dev

```bash
cd desktop
npm install                     # Electron downloads its binary on first run
ANYSCRIBE_DEV_PYTHON=$(pwd)/../.venv/bin/python npm start
```

`ANYSCRIBE_DEV_PYTHON` is any Python with anyscribe installed (the repo's
`.venv/bin/python` after `pip install -e .`). A relative path is taken from
the directory you start the app in; an absolute one is safest. Without it the start window says
the engine couldn't be found. Packaged, the app uses
`<resources>/python/bin/python3` instead.

The engine's output and one `[app]` line per start, stop, crash and restart go
to `~/.anyscribe/logs/app.log` (over 5 MB at launch: the last 1 MB is kept).
If that file cannot be written, the start window says "Can't write the log
file: <error>" and the engine is not started; Copy details still has the
lines kept in memory.
The Dock mode and the two first-launch questions already asked
(`oldLauncherAsked`, `terminalAsked`) are saved in Electron's userData folder,
`settings.json` (macOS: `~/Library/Application Support/anyscribe/`), never in
`~/.anyscribe`. Start at login is not saved there: the system's Login Items
are the source of truth.

## Tests

```bash
npm test     # unit tests (node --test): pure logic, plus the supervisor against test/fake-engine.js
ANYSCRIBE_DEV_PYTHON=$(pwd)/../.venv/bin/python npm run e2e   # the real app against the real engine
ANYSCRIBE_DEV_PYTHON=$(pwd)/../.venv/bin/python npm run e2e:removal   # old-launcher removal with the real uninstaller (port 8470 free)
```

`npm test` uses ports 8470 and 8471, so both must be free. The Terminal and
old-launcher tests make throwaway homes under the system temp folder and run
the real `zsh` and `bash` login shells against them (both must be installed). The e2e needs an
engine with slice 2a's hooks (`--watch-stdin`, `pid` in `/api/health`); its
last phase swaps in `test/fake-engine.js` to check frames, redirects and
popups, with a stand-in `xdg-open` that records instead of opening a browser. `npm run e2e`
starts Electron with no display (`--ozone-platform=headless`), a throwaway
HOME under `test/.tmp/`, and "dock" mode (a Linux tray icon would need the
desktop session); it stops every process by the pid it started or read from
the log. Run it with a clean environment (`env -i HOME=$HOME PATH=/usr/bin:/bin
ANYSCRIBE_DEV_PYTHON=... npm run e2e`) so nothing reaches your desktop session.

## Files

| File | What it does |
|------|--------------|
| `src/main.js` | Electron wiring: windows, menu bar and Dock, quitting, the bridges, links |
| `src/engine.js` | Starts, watches, restarts and stops the engine; the app log; port checks (Node only) |
| `src/logic.js` | Pure decisions: port, environment, job list to menu, quit question, crash window, start-window sentence |
| `src/preload.js` | `window.anyscribeDesktop`, the dashboard's bridge (below) |
| `src/terminal.js` | "Use from Terminal and Claude Code": our command in `~/.local/bin`, what Terminal runs, the skill (Node only) |
| `src/old-launcher.js` | The old browser launcher's three pieces, and removing them (Node only) |
| `src/run.js` | Runs a short helper command (login shell, `--version`, `install-skill`, `desktop uninstall`) in its own process group, with a timeout |
| `src/start.html`, `start.js`, `start-preload.js` | The local start window: "Starting", or "couldn't start" with Try again, Copy details, Troubleshooting guide |
| `assets/` | Menu bar icons and the start-window icon, generated by `npm run make-icons` from `src/anyscribe/assets/` (checked in) |

## How it behaves

- **Port**: the port the app last ran on (saved in `settings.json`, so the
  dashboard's per-port browser storage stays put), else 8470 or the next port
  up; never a port the older desktop mode records or serves (its
  `desktop.json` port, its login item's port read exactly with `plutil` on
  macOS, 8457, and a live old tray's own `--port`/`-p`), since its uninstall
  and the old tray's teardown stop whatever answers there. If the port answers or cannot be bound, the app shows
  "couldn't start" and never connects to or stops whatever holds it. The
  engine is ready only when `/api/health` reports the pid the app spawned;
  any other answer is treated as another program on the port, and nothing
  is sent to it.
- **Environment**: built from scratch, never inherited (see `buildEnv` in
  `logic.js`): HOME, a fixed PATH, `ANYSCRIBE_APP=1`, `PYTHONUSERBASE`
  `~/.anyscribe/runtime` with `PIP_USER=1`, LANG, PYTHONUNBUFFERED, TMPDIR, and
  packaged only `ANYSCRIBE_ELECTRON` and `<resources>/bin`. The add-ons folder
  `~/.anyscribe/runtime/lib/python3.13/site-packages` is created only for the
  packaged Python (a dev venv ignores it).
- **Start**: `<python> -m anyscribe ui --port N --no-open --watch-stdin` with
  stdin a pipe the app holds, so the engine stops when the app dies. The flag
  comes from slice 2a; an engine without it does not start.
- **Ready**: `GET /api/health` every 100 ms for up to 60 s.
- **Links**: inside the app only the engine's origin and the start page load.
  An outside link, popup or redirect opens in the browser; an outside frame is
  blocked.
- **Crash**: an exit after ready restarts the engine and reloads the dashboard;
  the third exit within 60 s stops retrying ("Engine stopped · couldn't restart").
  Any exit, before or after ready, also kills what is left of the engine's
  process group (its helpers: pip, yt-dlp, ffmpeg).
- **Stop**: close stdin and send SIGTERM to the engine's process group (it is
  spawned as its own group); if it has not exited after 10 s, SIGKILL the
  group. No HTTP request: whoever answers on the port later may not be ours.
- **Title bar**: on macOS the dashboard window uses `hiddenInset` with the
  traffic lights 16 pt in and 16 pt down, over the sidebar's top strip (the
  dashboard gives that strip its drag region and top padding). Elsewhere the
  default title bar.
- **Opened files**: a file dropped on the Dock icon or opened with the app
  (`open-file`, registered before ready) and absolute file paths on a second
  launch's command line are held until the dashboard window's page calls
  `onOpenFile`, then delivered in order and kept until the page acknowledges them; they also show the window. A new page
  (a reload, an engine restart) must subscribe again; until then files are
  held. Associating file types with the app is packaging (phase 3).
- **Windows**: closing hides; a second launch or reopening shows the window;
  a launch with `--hidden`, or one macOS reports as a login launch
  (`wasOpenedAtLogin`), opens no window. Not yet checked on macOS 13 and later.
- **Quit** (Cmd Q, the menus, logout, shutdown) is decided at once from the
  last job poll (at most 2 s old), so an idle logout is never held up. No job
  pending or running: the app quits, closing the engine's stdin and sending it
  SIGTERM. Jobs pending or running: the question "Transcriptions are still
  running" with Quit When Done (default), Stop and Quit, Cancel. Job list
  unknown (the last read timed out, failed or had the wrong shape): "anyscribe
  couldn't check which transcriptions are running" with the same three
  buttons. Quit When Done quits only on a known list with nothing left. Stop
  and Quit quits straight away: the engine's stop ends every job.
  A job started in the 2 s before quitting may not be asked about. During a
  logout, any question cancels the logout (macOS is told before the answer
  comes); after Stop and Quit, log out again.
- **Menu bar**: polls `GET /api/jobs` every 2 s (a failed read keeps the last
  list; from the third failed read in a row the header ends "· not answering",
  except that "anyscribe · Not answering" replaces the header when it would
  otherwise read "anyscribe · Ready")
  and shows Ready, Transcribing with each job's stage, Finished while the
  window was closed (failed first, then newest), or Engine stopped. Waiting
  and finished rows are capped at 5 plus "and N more waiting" / "and N more
  finished"; running rows always show. Dock mode: `menubar` (default), `both`, `dock`.

## The bridge: `window.anyscribeDesktop`

Only the dashboard window gets it (preload with contextIsolation, sandbox, no
Node). Calls from any other page are refused. This is the contract the
dashboard's Mac screens build on.

| Member | Gives |
|--------|-------|
| `version` | The app's version (string) |
| `platform` | `process.platform` (`"darwin"` on a Mac) |
| `getSettings()` | `Promise<{dockMode: "menubar" \| "both" \| "dock", startAtLogin: boolean}>` |
| `setDockMode(mode)` | Applies immediately and saves. Rejects an unknown mode |
| `setStartAtLogin(on)` | Registers or removes the login item (`app.setLoginItemSettings`). `getSettings().startAtLogin` reads it back from the system, so it is false while macOS waits for approval in Login Items |
| `engineStatus()` | `Promise<{state, port, lastExit, stoppedRestarting}>`: `state` is `"starting" \| "running" \| "restarting" \| "stopped"`; `lastExit` is `{code, signal, reason} \| null` (`reason`: a sentence, or the engine's last stderr line, or null when none was reported); `stoppedRestarting` is true after three exits in a minute |
| `onEngineStatus(callback)` | Calls `callback(status)` on every change; returns an unsubscribe function |
| `restartEngine()` | `Promise<{ok, reason}>`. Refused while any job is pending or running (`reason: "Wait for transcriptions to finish before restarting the engine."`) or while the job list cannot be read (`reason: "anyscribe couldn't check for running transcriptions; try again in a moment"`) |
| `openLogFolder()` | Opens `~/.anyscribe/logs` in Finder |
| `revealInFinder(path)` | Shows that file in Finder. Needs an absolute path |
| `pathForFile(file)` | The local path of a dropped or picked `File` (`webUtils.getPathForFile`), so it is read in place instead of uploaded |

### Bridge v2

Every result below carries `ok`, and `reason` (plain words) when not ok; a
`reason` can also come with `ok: true` to explain a state (the login shell
couldn't be asked, the skill couldn't be installed, a changed command was
left alone).

| Member | Gives |
|--------|-------|
| `terminal.status()` | `{ok, reason, state, command, uses, appVersion, claudeCode, skill}`. `state`: `"off"` (no command of ours), `"on"` (Terminal runs ours; also when ours is written and the login shell couldn't be asked, with `reason` saying so), `"other-copy"` (Terminal runs a different anyscribe first), `"path-missing"` (ours is written, the login shell finds no anyscribe). `command`: our command's path, or null. `uses`: `{path, version, via: "uv" \| "pipx" \| "pip" \| "app" \| "unknown"}` or null (an alias or function: path null, via unknown). `occupant`: `{path, via, version}` for whatever sits at `~/.local/bin/anyscribe` when it is not ours, else null; offer "Switch to this app's copy" only when it is set. When ours is written but another copy comes first, `reason` is "Terminal finds another anyscribe at <path> first." `claudeCode`: `~/.claude` exists. `skill`: `"installed" \| "missing" \| "not-applicable"` |
| `terminal.turnOn({replace})` | Writes our command. With another file at `~/.local/bin/anyscribe` and no `replace: true`: `ok: false` (state `other-copy` when Terminal runs it), nothing touched. With `replace`, the other file or symlink is moved to `~/.anyscribe/runtime/replaced/anyscribe` (an older one there is renamed with a timestamp, never deleted). Then, if `~/.claude` exists, `python -m anyscribe install-skill --force`. `ok: false` only when the command was not written; a failed skill shows as `skill: "missing"` with `reason` until a later install succeeds, even when an older skill folder is still there. Writes are committed by the record: temp files with fresh names created exclusively (a file or symlink already at a name is never written through), the record first (the new hash, the current one still accepted as `previousSha256`), then the file moves; a record that cannot be saved leaves the command untouched |
| `terminal.turnOff({choice})` | Removes ours only if it is still ours (marker and recorded hash); puts back what it replaced in one rename. If ours was changed or removed since and something can be put back: `{ok: false, needsChoice: "keep-current-or-restore", reason}`, nothing touched. Answer with `turnOff({choice: "keep-current"})` (leave the current file, forget ours) or `turnOff({choice: "restore"})` (the current file is moved aside into `replaced/`, the old one put back). A changed command with nothing to put back is left as it is (`ok: true`, `reason` says so). Then the skill folder `~/.claude/skills/anyscribe` is removed only if the login shell finds no anyscribe at all (unknown keeps it) |
| `terminal.addToPath()` | `{ok, file, line}`: appends `export PATH="$HOME/.local/bin:$PATH"` to `~/.zprofile` (zsh) or `~/.bash_profile` (bash), creating it if missing, never twice. Then it asks the login shell again: if `~/.local/bin` is still not on PATH, `ok: true` with the reason "The line is in ~/.zprofile, but your shell setup removes it again later (check ~/.zshrc)." Not ok for any other shell, and for bash when `~/.bash_profile` is missing but `~/.bash_login` or `~/.profile` exists (creating it would hide them): `reason` gives the line to add by hand |
| `terminal.retrySkill()` | Runs `install-skill --force` again; `ok` when the skill is installed |
| `oldLauncher.status()` | `{ok, installed, pieces: {launcher, loginItem, menuBarIcon}, lastRemoval}`: `~/Applications/anyscribe.app` and `~/Library/LaunchAgents/com.anyscribe.tray.plist` `"present" \| "absent"`; the old menu bar icon `"running" \| "not running"` (`~/.anyscribe/tray.pid` names a live process whose command line is an anyscribe tray). `installed` (any piece left, a running old menu bar icon alone included) is true only on macOS. `lastRemoval`: `{ok, pieces, startAtLoginCarriedOver, reason, at}` of the most recent removal, kept by the app across the dashboard's reload, or null |
| `oldLauncher.remove()` | macOS only. Pauses the app's engine: refuses exactly like Restart engine (transcriptions running or waiting, the list unknown, a restart under way), with its reason, `pieces: null`, and nothing run. While the uninstall runs, nothing can start the engine (a restart says "The old launcher is still being removed."), and quitting kills the uninstall at once. Otherwise the engine restarts around the removal (the dashboard reloads; the menu reads Restarting), and between the old engine's exit and the relaunch it runs `python -m anyscribe desktop uninstall --json` with the engine's environment, then checks each piece itself: `{ok, pieces: {launcher: "removed" \| "still there", loginItem: "removed" \| "still there", menuBarIcon: "stopped" \| "still running"}, startAtLoginCarriedOver}`; ok only when all three are gone. When the old login item was there before and is gone after, the app's own Start at login is turned on; `startAtLoginCarriedOver` is true only when the system then reads it as enabled, else `reason` says what macOS needs (approval in System Settings, General, Login Items). If the engine does not start again, `reason` says so, and the start window's "couldn't start" also says the removal ran, with its result |
| `firstLaunch.get()` | `{ok, oldLauncherAsked, terminalAsked}` |
| `firstLaunch.mark(key)` | Records `"oldLauncherAsked"` or `"terminalAsked"` as asked; any other key is rejected |
| `onOpenFile(callback)` | Calls `callback(absolutePath)` for each opened file; held files arrive on the first subscribe. Returns an unsubscribe function. Only the dashboard window's page can subscribe. The app keeps each file until the page acknowledges it (the preload does, after the callbacks ran), so an unsubscribe or reload in between never loses it, and an acknowledged file is never sent again |

The Terminal command is one POSIX sh script, `~/.local/bin/anyscribe`. Line 2
is the marker `# anyscribe-mac-app-command <version>: ...`; it exports
`ANYSCRIBE_APP=1`, `PIP_USER=1`, `PYTHONUSERBASE="$HOME/.anyscribe/runtime"`
(packaged: also `<resources>/bin` first on PATH and `ANYSCRIBE_ELECTRON`), then
execs the app's Python with `-m anyscribe "$@"` (dev: the resolved
`ANYSCRIBE_DEV_PYTHON`). Its hash, and what it replaced, are recorded in
`~/.anyscribe/runtime/terminal.json`. What Terminal runs is asked of the login
shell (`$SHELL -lic`, else the account's shell) with a fixed starting PATH,
random begin and end markers around the answer, and a 5 s limit; no Terminal
profile file is ever parsed.
