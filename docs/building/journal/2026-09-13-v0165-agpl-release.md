# v0.16.5 — first AGPL release

The user authorized merging and publishing after the read-only Claude audit and
fixes. [PR #14](https://github.com/rishmadaan/anyscribe/pull/14) was squash-merged
as `ecf3583`; its final Python 3.10/3.12, frontend, docs, and preview checks passed.

Version 0.16.5 marks the release boundary from MIT to AGPL-3.0-or-later. Existing
MIT versions remain unchanged. The distribution expression also names bundled
MIT/ISC components; this does not offer an MIT alternative for first-party code.
The release includes editable frontend source, dependency notices, and standalone
skill licensing. See the [adoption](2026-09-13-agpl-license-adoption.md) and
[audit](2026-09-13-agpl-pr-audit.md) journals for implementation and test evidence.

Both Python version fields and the changelog/backlog are updated together.
README and landing copy now describe the release rather than a future migration.
No user-facing commands or configuration changed during release preparation.

Release procedure: use the documented manual alternative to `release.sh` on
Windows, commit the prepared version/docs, check CI, and push only `v0.16.5` to
trigger trusted PyPI publishing. The tag identifies matching source for this
release. GitHub release notes explicitly announce the license transition and
link to the exact source archive; post-publish verification inspects both PyPI
artifacts and installs the published package in an isolated environment.

## Published and verified

`v0.16.5` points to release commit `9ea09e0`. The
[publish workflow](https://github.com/rishmadaan/anyscribe/actions/runs/34750500315)
passed lint, tests, frontend checks, package build and tag/version validation,
then published the wheel and sdist to PyPI and created the
[GitHub release](https://github.com/rishmadaan/anyscribe/releases/tag/v0.16.5).
Release notes were updated with the AGPL transition and exact-version source link.

Post-publication checks downloaded both artifacts from PyPI, verified their
SHA-256 digests against PyPI metadata, and inspected their license/source files.
PyPI reports `AGPL-3.0-or-later AND MIT AND ISC`; GitHub recognizes AGPL. The live
production landing page shows AGPL and preserves the historical MIT boundary.

A fresh environment outside the checkout installed `anyscribe==0.16.5` from
PyPI. Version/help, doctor invocation, pip-install detection, update checking
(reports up to date), standalone skill license/copyright installation, and
dashboard/health/third-party-notice routes passed. User configuration was isolated.

The separate main-branch CI run was still queued during verification; the
publishing workflow independently passed its required gates before uploading.
No tags or previously published MIT artifacts were replaced.
