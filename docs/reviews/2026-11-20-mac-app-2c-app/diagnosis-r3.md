# Diagnosis, round 3 (claude-fable-5-2, read-only, Agent tool), summary

Launcher: each fix guarded a model of the uninstaller instead of removing its target. stop_tray has three kill paths (POST by port, the tray pid, server.pid checked only as alive and running `anyscribe ui`); the app's engine is indistinguishable from the old server by design. The app re-implemented Python's plist reading in JS, and every launcher test swapped the uninstaller for a stand-in, so tests proved the mirror agrees with itself.
Command writes: ownership lives in two files with no single commit point; C4 moved the unsafe moment to the other side (A4), and the new temp file was a write the foreign-file guard never covered (A3); the fault test failed at the first write.
Recommendation: (b) remove the target. Run the uninstaller inside Engine.restart() between the old child's exit and the relaunch (restart already refuses on running, waiting or unknown jobs and blocks a second restart; a plain stop would show "Couldn't start" for the gap); relaunch whether or not the uninstaller succeeded; a quit in the gap spawns nothing; keep the last removal result in main and return it from oldLauncher.status() because the page reloads on "running". For writes: record first with both the new and previous hash accepted; exclusive-create random temp names; no rollback needed; crash-safe.
