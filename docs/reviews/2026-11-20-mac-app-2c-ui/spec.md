# Spec: phase 2c-ui, the new screens inside the dashboard (ui/)

Build the dashboard side of the approved Mac app screens. The design and every word on these screens is the approved mockup at the approved mockup (kept privately; its sha256 starts bcf26037) (final, sha bcf26037; read its HTML, it is the binding source for wording and states): sections 3 (old launcher question), 4 (Terminal and Claude Code), 5 (Transcribe inside the app), 9 (Settings "This Mac"), 10 (engine trouble banner) and "For the build". The app side (bridge-v2.md) is built in parallel in desktop/ by slice 2c-app; code against the contract.

## Rules
- Everything new appears only when `window.anyscribeDesktop` exists. In a browser the dashboard is exactly as today (same pages, Shutdown button, Startup section, upload-based Browse). One small helper module reads the bridge, with types for bridge v2.
- Keep: today's look and tokens (ui/src/index.css), the sidebar credits and KraftedX mark, the onboarding wave's wizard behaviour (OnboardingWizard: never lock closing during a download; the local step owns the setup watch; do not reopen BACKLOG items L1 or R2L1).
- Words come from the mockup. Where the mockup has no words for a state the bridge can produce, write plain words in the same voice and list each one in proof.md for review.

## Screens
1. Layout, inside the app: hide the sidebar's Shutdown button (quitting is the app's job). On macOS, a drag strip across the top of the sidebar (CSS app-region drag; controls inside it no-drag) and top padding so the traffic lights clear the logo.
2. Engine trouble banner (mockup section 10), at the top of every page, driven by `onEngineStatus`: "restarting" shows the restarting banner; running again after a restart shows "Running again" with the unfinished-job wording only when the page was watching a job at the time (name it; "Check History before starting it again"; buttons Open History and Dismiss); `stoppedRestarting` shows "The engine keeps stopping" with the last exit (code or signal; "the reason wasn't reported" when none), Restart engine (shows the bridge's reason if refused), Copy details and Troubleshooting guide.
3. Settings, inside the app: the "This Mac" section of mockup section 9 replaces today's Startup section. Rows: Show anyscribe in (three choices, wording under it changes with the choice), Start at login (state read from getSettings, which reads the system), Use from Terminal and Claude Code (every terminal.status state with its line: on, off, other copy, Terminal can't see it yet with an "Add it for me" that asks before calling addToPath, skill missing with Try again, the turnOff conflict with Keep current command and Restore previous command), Updates (the app version only for now; update states come in phase 3), Engine (state words, Restart engine disabled with the mockup's reason while transcriptions run, Open log folder), Old browser launcher (only while installed; Remove it, with the per-piece result), Removing anyscribe (the mockup's help text; the transcripts folder shown is the real workspace path from the existing workspace API).
4. First launch inside the app (mockup sections 3 and 4): if the old launcher is installed and not yet asked, its question first (Remove the old launcher / Keep both, with the notes the mockup carries), then its result card (removed, or the cleanup checklist with Try again). Then, if not yet asked, the Terminal card: for new people as the optional last step of the setup wizard (Turn on / Skip for now), for people who already finished setup as a one-time card labelled "One more option". Mark each as asked through firstLaunch.mark so it never repeats.
5. Transcribe inside the app (mockup section 5): Browse uses the native picker and `pathForFile`, then submits the path (no upload copy). Dragging a file over the window shows the "Drop to transcribe" overlay with its name and size; dropping submits its path. Files from `onOpenFile` (the Dock icon) are submitted the same way.

## Done bar
- `npm run build` and `npm run lint` in ui/ pass; commit the rebuilt bundle in src/anyscribe/web/static as the repo does.
- A click-through check script (Python Playwright, already installed on this machine; keep it in this packet folder under checks/, not as a repo dependency) runs the built dashboard against a real engine from the main checkout's .venv with a throwaway HOME, with a stub `window.anyscribeDesktop` injected before load that can be put into every state above. Click every control in every state, check what each one calls on the stub and what the screen then says, and screenshot each state at 1440, about 1000 and 390 px. Read the screenshots yourself. Also run once with no stub and show the browser dashboard is unchanged (Shutdown present, Startup section present, no This Mac).
- Mutation-test the guards: nothing app-only renders without the bridge; addToPath is never called without the person's yes; the first-launch questions never repeat once marked; Restart engine is disabled while transcriptions run.
- Docs: docs/building/architecture.md (dashboard inside the app), the journal entry for 2c-ui and its _index row, docs/user only if a user-facing behaviour in the browser changed (it should not).
