# Diagnosis, round 3 (claude-fable-5-2, read-only, Agent tool), verbatim summary of its findings

Why the fixes kept missing: each round repaired the instance named, not the invariant. Invariants never written down: (1) the final path only ever holds the whole content; (2) when a watched engine is gone, by any route, nothing it started is still running. The write fix used a helper made for small config files (one raw os.write, result ignored). The child fix covered one of four exit routes: hard-exit timer (covered), server.run() returning (A2), SIGTERM (uvicorn re-raises the captured signal inside server.run() with the default handler, so nothing after it runs; the shell's quit sends exactly stdin end plus SIGTERM, so every normal quit orphans children), and the shell's SIGKILL by pid (the engine cannot react).

What the tests miss: every test mirrors its patch; the write test swaps os.write for one that raises; the held-engine test is a stand-in that never calls run(); the only real-engine stop test stops an idle engine with no child and no SIGTERM; in-process tests record call order, not outcome; the shell tests' fake engine has no children.

Recommendation: (A) atomic_write writes through a buffered file object, flush, fsync, then os.replace; unlink the temp on any failure. (B) watch-stdin mode only: one exit door; SIGTERM and SIGINT handlers call _exit_hard; server.run() wrapped in try/finally calling _exit_hard; the timer stays. (C) the shell spawns the engine detached (its own group) and kills the group. Tests: a real kernel short write via RLIMIT_FSIZE; the real run(watch_stdin=True) with a held child, parametrized over stdin close, SIGTERM, both, and a held server, asserting the group is gone; a shell fake engine with a grandchild. Risks: a watched engine always ends by signal 9; jobs get no grace after the server stops; pip can be killed mid-install; fsync adds milliseconds on the CLI path; mkstemp makes 0600 files, so transcripts written through atomic_write lose today's 664 permissions (unflagged change from round 1), and a hard kill can leave a stray temp file in the vault.
