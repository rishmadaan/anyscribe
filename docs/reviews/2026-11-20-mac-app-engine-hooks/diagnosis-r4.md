# Diagnosis, round 4 (claude-fable-5-2, read-only, Agent tool), summary

Why atomic_write kept failing: each round swapped the primitive to fix the reported symptom and silently dropped a property the old one gave (write_text: whole write and umask bits; mkstemp plus os.write: atomic and private but short writes; open("xb"): whole write and umask bits but no privacy, chmod bolted on). The contract was never one list, and every permission test looked at the final path after the call while the defects live in the temp file during the call.

Design: the creation mode is the fix (a file created wide and narrowed later can be opened empty and read through the kept descriptor); os.open(tmp, O_WRONLY|O_CREAT|O_EXCL|O_BINARY if present, mode) outside the try; os.chmod (not fchmod, missing on Windows before 3.13) to the existing bits right after creation; buffered write, flush, fsync, os.replace; unlink on failure. Never read the umask (os.umask is set-and-restore and races threads). Tests: the temp's mode observed at fdopen and at fsync for an existing 0600 file; new files under umask 022 and 002; an existing 0664 file under umask 022 stays 0664. Next likely finding: new config, index, state, manifest and tailnet files were born 0600 before the branch and would now be born at the umask default.
